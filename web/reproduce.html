The public laboratory works without a Python server. Interactive simulations are computed on your device; neural comparisons, loss curves and residual maps come from completed, archived Python experiments.

What runs in the browser?

The forward solver uses the same conservative spatial fluxes, heating boundary and M0–M3 hypotheses as the Python solver. It integrates with fourth-order Runge–Kutta and a bounded time step. The Python reference uses BDF. These are distinct numerical methods: browser exploration does not replace the recorded research benchmark or train a PINN.

Reproduce an experiment

Download Python training kit ↓

Extract the ZIP. Install Python 3.12, open a terminal in the extracted folder and run: 

python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python main-2.py run --config configs/demo.json --output results/my-demo

On Windows, use py -3.12 -m venv .venv and replace .venv/bin/python with .venv\Scripts\python.exe.

For the enhanced single-seed model use configs/advanced-demo.json; for five seeds use configs/advanced.json. Always choose a new output folder. The kit includes numerical source, configuration and pinned dependencies; it is not a full copy of the website.

The environment was tested on macOS CPU. Other platforms should verify their installation. Local training uses your device’s resources and does not upload results to the public site.

What the evidence means

Archived experiments use synthetic data. Seed spread describes optimizer variability, not calibrated uncertainty over physical measurements. Direct neural predictions and predictions from inferred coefficients are reported separately. Exact boundary constraints do not establish physical validation.

New experiments can be published by the project maintainer through a new site build. Your browser does not modify the published archive.
